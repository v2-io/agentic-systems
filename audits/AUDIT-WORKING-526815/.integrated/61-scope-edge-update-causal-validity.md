# 61 - scope-edge-update-causal-validity

Source: `01-aat-core/src/scope-edge-update-causal-validity.md`

## First-pass understanding

This segment scopes when strategy-edge updates can retain interventional semantics. It distinguishes data generated by the agent's action loop from clean causal identification, then adds attribution and execution-context variation as necessary gates. The resulting three-regime table is a useful guardrail: some edge credences approximate interventional quantities, some are partially identified, and some are only associational proxies.

The important addition is the identifiability coefficient `iota_ij`, which separates "can I observe the outcome?" from "can I attribute the outcome to this edge?" That is the right distinction, even if multiplying the gain by a scalar identifiability coefficient is only a first-order approximation.

## Diagram attempt

I focused the diagram on the action-leaf typing issue. The agent can usually perform `do(attempt a)`; whether the leaf proposition `i = action a succeeds` becomes true is itself an outcome. The causal edge update is clean only after the success outcome and the child outcome pass attribution and context-variation gates.

## Findings and watches

- F57 candidate: the segment says action leaves are propositions like "action `a` succeeds" and that executing the action gives `do(i)`. Executing an action usually intervenes on the attempt, not on the success proposition. If `i` means "success achieved," then the edge quantity should be conditioned on/intervened through `do(attempt a)` plus observed `i`, or the leaf variable should be renamed to the action attempt event.
- F58 candidate: C2 says attribution is trivially satisfied for single-parent nodes. That is only true under causal sufficiency/isolation. A represented single parent does not exclude unrepresented exogenous causes or background trends that also advance `j`.
- F59 soft candidate: "Software as Regime A" is too broad. Some software tests are isolated and CI-like, but real software updates can have flaky tests, shared infrastructure, hidden dependencies, concurrent changes, and environment drift. Software can be Regime A for well-isolated test/action edges, not as a domain-wide default.
- Watch: C3 should distinguish `P(j | do(i))` under a target context distribution from `P(j | do(i), selected context)`. Selection bias is resolved either by randomization/coverage or by making context part of the estimand.
- Watch: the combined gain repeats the mixed-metric issue from `hyp-edge-update-via-gain`; `iota_ij` is plausible as a discount factor, but the base uncertainty ratio still needs a common scale.

## Local verdict

The scope structure is valuable and mostly points in the right direction. The action-attempt versus action-success typing should be fixed before using the segment's `do(i)` notation as theorem-grade.
