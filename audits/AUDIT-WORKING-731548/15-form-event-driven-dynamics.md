**14. Wandering thoughts.** *One:* the typed-event alphabet is extensible by design (obs, act) — and the framework will need at least two more types it hasn't named: *internal* events (consolidation pseudo-events, deliberation completions — ledger xxxiv) and *null* events (scheduled ticks with no content, which carry information exactly when silence is informative: the watchdog that didn't bark). Null events are a real subtlety: $\mathcal I(\text{nothing arrived in } [\tau, \tau'])$ can be large (absence of expected events updates the model), but an event-*driven* update rule literally cannot fire on absence. Every practical monitoring system solves this with timeouts — i.e., self-generated events — which quietly reintroduces a clock into the "clockless" formulation. The two-clocks seam (3b) and the null-event gap are the same issue at different depths: pure event-driven dynamics cannot express "too long since," and adaptive agents live and die by "too long since." I'd rank this the chapter's most interesting unnamed limitation, and it's cheap to name honestly.
