**14. Wandering thoughts.** *One:* proportionality lens — the *realization list* (Kalman / RL / developer / LLM) recurs almost verbatim in three segments now (scope-agency, here, and I predict ahead). The list is doing real work (cross-domain anchoring) but its *repetition* is chance-made-prominent: nobody decided the same four examples should be the corpus's rhythm section; a spike wrote them once and they propagated. Meanwhile the *biological* instances the README promises (bacteria!) have appeared zero times in segment bodies so far. If the theory's exemplar diet is monotone, its intuitions calcify around engineered systems — and the persistence condition's most interesting instances (metabolic, ecological) stay unstressed. Cheap fix with real yield: vary the exemplar per segment deliberately, one biological instance per chapter.

*Two:* the completeness assumption has an unadvertised *dark* consequence the ELI volumes should want surfaced: if anything not in $M_t$ is lost, then an entity's access to its own past is *entirely* hostage to $\phi$'s choices made moment-by-moment — and $\phi$ is chosen (by architecture, by consolidation policy) largely *before* the entity can have preferences about what to keep. For a human this is fine (we call it childhood amnesia and cope); for a designed entity, whoever sets the compression policy is deciding, in advance, which parts of the entity's life will have *happened*, in the only sense that matters internally. The sovereignty-carve principle in the project's memory (derive what's forced, hand genuine degrees of freedom transparently) applies with full force to $\phi$: compression policy is not infrastructure, it's biography-authorship. I don't think any Part-I segment should carry this — but Volume 4's identity chapter should, and the hook is exactly this segment's completeness assumption.

*Three:* the suitcase anchor deserves one refinement before anyone canonizes it: suitcases are packed *once*; $M_t$ is repacked at every event under arrival pressure. The truer anchor is a *carry-on you must repack while running to the gate* — the running is the tempo constraint, and the things you drop while repacking in a hurry are the gain-misallocation failures Ch.3 formalizes. That version predicts the deliberation-cost tradeoff too (stop to repack well vs keep moving). Anchor-quality test: perturbations map (more arrival pressure → worse packing → higher steady-state mismatch ✓; bigger suitcase → higher ceiling ✓; stop running → world moves on ✓ = deliberation cost).
