# Hypothesis: Exponential Cognitive Load

If context-switching compounds multiplicatively, implementation time grows exponentially with the number of boundary crossings (discontinuities) in a changeset.

## Formal Expression

*[Hypothesis (exponential-cognitive-load)]*

$$t_{\text{actual}} = t_{\text{baseline}} \times k^{\text{discontinuities}}$$

where $k \gt 1$ is the compounding factor per context switch.

Even modest values of $k$ (1.1 to 1.2) create substantial differences when compounded across many discontinuities.

## Epistemic Status

*Hypothesis.* TST states this carefully as a hypothesis requiring validation, and that caution is warranted. The actual relationship may be:
- Linear ($k = 1$ with additive cost per switch)
- Sub-exponential (diminishing marginal cost of additional switches)
- Exponential (as hypothesized)
- Dependent on the *structure* of dependencies between scattered changes

AAT's #der-deliberation-cost framework suggests a refinement: the functional form likely depends on the dependency structure of the scattered changes, not on the count of discontinuities alone. Independent changes across many files may cost linearly (each context switch is independent). Interacting changes across many files — where understanding the change in file A requires understanding the change in file B which requires understanding file C — may cost exponentially because the agent must hold multiple contexts simultaneously to reason about their interactions. The distinction is between parallel context-loading (linear) and nested context-dependency (potentially exponential).

The one non-circular measurement available bears on the count form only, and disfavors it: at file and directory granularity, the elapsed time between a developer's consecutive commits rises with the number of crossings in the commit and shows no compounding. In the largest of three histories a pure exponential in the count is rejected for a power of $(1+d)$ with exponent 0.72–0.86, depending on how time away is modelled; in the other two the forms cannot be told apart (Discussion). That measurement is *heuristic* tier: inter-commit elapsed time is a proxy for implementation time, separating working time from time away is a modelling choice, and the evidence comes from three histories, each mostly one developer's. The structure-dependent form is untested.

## Discussion

**Why the hypothesis persists.** Despite lacking formal derivation, exponential cognitive load explains a robust observation: developers strongly prefer consolidated changes, and scattered changes feel *disproportionately* difficult. The hypothesis provides a quantitative framework for this observation. If the cost is superlinear in the crossings, whether exponential or not, reducing discontinuities has increasing marginal returns. Counted crossings alone do not show that superlinearity in the measurement below, so the disproportion developers report, if it is real, has to come from something the count leaves out; the dependency structure among the changes is the candidate this segment's Epistemic Status names.

**Connection to AAT's deliberation cost.** The #der-deliberation-cost framework formalizes the cost of reasoning before acting. Context switches during implementation are a form of deliberation cost — the agent must reason about how changes in one location affect another. When the changes are independent, this deliberation is parallelizable (each change can be understood locally). When they interact, deliberation becomes sequential and potentially recursive: understanding change A requires understanding change B, which may require understanding change C. This recursive dependency structure is what could produce genuine exponential scaling.

**Discontinuity hierarchy.** *[Discussion — taxonomy, not derived.]* Not all discontinuities are equal. The cost per boundary crossing increases with the type of boundary:

1. *Lexical*: Symbol must be found elsewhere in the same file
2. *File*: Must open another file and load its context
3. *Module*: Must understand another module's conventions, invariants, and vocabulary
4. *Service*: Must understand another service's API, data model, and failure modes
5. *Network*: Must trace through network calls, serialization, and distributed state

Each level roughly doubles the context-loading cost (the $k$ factor increases with boundary type). This is a heuristic observation, not a measured result — the actual cost ratios are an empirical question. The measurement below treats file and directory crossings only, with directory crossings weighted twice; whether the doubling-*per-boundary-type* heuristic holds is untested.

**A git-history measurement of the count form.** *[Empirical Claim — heuristic tier; elapsed time between commits as the time measure.]* For each commit, the discontinuity score is $d = (\text{file transitions}) + 2 \cdot (\text{directory transitions})$ over its changed paths, and the time is the elapsed time since the same author's previous commit. Three histories were measured. The first is the repository in which TST itself was written: mostly prose, about half of its 316 commits co-authored by an AI agent, its pairs falling on twelve working days. The other two are the open-source projects obsidian-linter and ink. In each, the measured pairs come mostly from one person: 71% of obsidian-linter's from one author, and 80% of ink's from one of the three authors left once squash merges are out. A pair with a squash-merged pull request at either end (the "(#N)" subject a squash merge carries) is left out, because a squash merge's timestamp is the merge, not the work. That keeps 358 of ink's 493 pairs at $d \le 25$ and 1,183 of obsidian-linter's 1,264. Between 216 and 1,183 pairs enter each fit, depending on repository and on how long gaps are treated. The intervals below resample whole author-days, since gaps within one working session are not independent. Long gaps are the difficulty. A gap of hours or days holds time away from the work, and dropping the gaps above a session cap drops more of them at high $d$: in obsidian-linter a 24-hour cap drops 13% of gaps at $d = 0$ and 27–35% at $d \ge 11$. Two treatments are reported. One keeps gaps under session caps from 60 minutes to 24 hours. The other keeps every gap and fits a two-component mixture to $\log T$: a working component whose mean carries the form in $d$, and an idle component, with the working share free in each $d$ bin.

1. Elapsed time rises with $d$. Under session caps of 60 to 240 minutes, Spearman $\rho$ = 0.39–0.45 in the corpus and obsidian-linter and 0.15–0.18 in ink; after partialling out lines changed, 0.17–0.37 and 0.06–0.09. The mixture's working-time medians rise with $d$ in obsidian-linter (6.1, 12.1, 16.3, 34 and 28 minutes for $d$ = 0, 1–2, 3–5, 6–10 and 11–25; the last bin's interval is 16–50 minutes) and in the corpus (3.1 to 16.4 minutes). In ink they rise to 13 minutes at $d$ = 3–5; the two higher bins' intervals, 5–37 and 1–137 minutes, are too wide to say whether the rise continues.
2. In obsidian-linter, the largest history, a pure exponential in the count is rejected. Fitted inside the working component, $\log T = c + a\,d + b\log(1+d)$ gives $b = 1.01$ (95% interval $[0.61, 1.33]$) and $a = -0.08$ $[-0.18, +0.06]$, where the exponential form predicts $a \gt 0$ with $b \approx 0$. As a pure power law, $T \propto (1+d)^{\beta}$ with $\beta = 0.72$ $[0.56, 0.88]$. With time away modelled as two components instead of one, $\beta = 0.86$ $[0.69, 1.05]$; that likelihood has several optima, and this is the best of thirty starts. In ink and the corpus the forms are not distinguished. Their working-time exponents are 0.30 $[-0.04, 0.76]$ and 0.50 $[0.17, 0.84]$, $b$'s interval reaches zero, and the power law's log-likelihood exceeds the exponential's by 0.8 and 1.6.
3. The capped fits point the same way and do not decide by themselves. At every cap from 60 minutes to 24 hours, $a$ is near zero or negative and $b$ is 0.38–1.04. But a pure exponential in working time, mixed with idle gaps as fitted to each history and then capped, also gives $b$ up to about 1, because the cap attenuates an exponential rate toward zero, and it sometimes gives a negative $a$. Over 1,000 simulated histories it reaches the observed $b$ in 1.5–9.5% of draws and the observed $a$ in 1.3–8.9%, depending on history and cap. Those eight readings per history (four caps, two coefficients) reuse the same gaps, so the test is their smallest tail share, set against how often the null's own replicates produce one as small. They do so in 4.7% of replicates for the corpus, 5.8% for obsidian-linter and 6.2% for ink. All three sit at the edge of a 5% test, within the simulation's error of it. The capped fits lean against a pure exponential in every history and, alone, settle it in none.

Where these data discriminate, then, the count form's cost grows as a power of $(1+d)$ that is at most about proportional: 0.72 with time away as one component, 0.86 with two. Where they do not, they cannot tell a power law from an exponential. Nothing in them shows compounding. A single exponential forced onto the same data returns a per-discontinuity rate of 0.02 to 0.17 depending on the fitting method and the cap, and 0.07 to 0.30 inside the working component. That number is not evidence for the form. In squash-merged histories (gemini-cli, codex), with the merges kept, the timestamps record merge cadence rather than work, and there $d$ barely predicts the gap ($\rho \approx 0.1$).

Limits: elapsed time between commits includes everything else the developer did and depends on how they chose to cut commits. It is a proxy for implementation time, not a measure of comprehension. The mixture that separates working from idle time is a modelling choice, with log-normal components, and the exponent moves with it. With two idle components the fit degenerates in ink and the corpus (in ink, a narrow working spike beside an 8-minute "idle" component), so that variant is informative in obsidian-linter only. In ink even the one-idle mixture is weakly identified. Its likelihood is highest, by 1.4 to 2.1 depending on the form, with the labels swapped: a 7-minute "idle" component and the time away carrying $d$. Ink's reported numbers come from the fit with time away above working time, which is the reading the method needs. So ink is best read as a history in which the method cannot separate work from time away. In obsidian-linter and the corpus the reported fits are the best of thirty random starts. The score counts crossings without regard to whether the changes depend on one another, so the measurement tests the count form only. The structure-dependent form in the Epistemic Status, under which interacting changes compound and independent ones do not, needs a measure of dependency among the changed locations, and it is untested. The result is consistent with that form's prediction that most commits, whose changes are largely independent, cost about additively or less. It is equally consistent with a world where nothing compounds.

A second operationalization exists and is unmeasured. The theory's original statement of this hypothesis counted not boundaries crossed by a changeset but *comprehension searches* while reading code. These are symbol-resolution and usage searches, type and behavior inference gaps, and switches between files, scored as $\sum_{\text{element}} P(\text{search}) \cdot \text{cost}(\text{search})$. That count lives on the reading side, where #der-change-proximity-principle's reading-locality companion also lives. It needs instrumented reading (IDE navigation logs, agent tool-call traces), which git does not record.

**The comprehension-changeability tension.** *[Discussion — architecturally consequential.]* Conventional advice emphasizes small, focused units (functions, classes, modules) for changeability — changes are isolated, tests are targeted, coupling is reduced. But small units create comprehension discontinuities: understanding the flow requires jumping between many fragments. This creates a genuine tension:

- Fewer, larger units → fewer discontinuities → faster comprehension → but higher coupling, larger changesets
- Many small units → more discontinuities → slower comprehension → but lower coupling, smaller changesets

A resolution follows from #der-change-investment: the right balance depends on $\hat n_{\text{future}}$. For young code ($\hat n_{\text{future}}$ small), the comprehension cost of fragmentation is paid on every interaction but the changeability benefit is realized rarely — favor continuity. For mature, heavily-modified code ($\hat n_{\text{future}}$ large), the changeability benefit dominates — favor modularity. The crossover point is where the cumulative comprehension cost of fragmentation equals the cumulative changeset-size savings from isolation. This crossover is not derived but is testable: compare total development time for features implemented in consolidated vs. fragmented code at different change-history depths.

**Anti-patterns that create unnecessary discontinuities.** *[Discussion — pattern catalog, empirically grounded.]* Several common practices create discontinuities without corresponding changeability benefits:

- *Premature abstraction*: Extracting interfaces or abstract classes before the variation they're meant to accommodate has actually appeared. Creates discontinuities now for benefits that may never materialize.
- *Over-interfacing*: Placing interfaces between components that always change together. The interface adds a discontinuity but provides no isolation benefit since both sides change simultaneously.
- *Excessive indirection*: Chains of delegation (A calls B which calls C which calls D) where each hop requires the reader to find and understand the next link. The call depth is a direct measure of discontinuity count.
- *Naming minimalism*: Abbreviated or generic names (e.g., `mgr`, `svc`, `impl`) that force the reader to look at the implementation to understand what the component does, adding a discontinuity that a descriptive name would have eliminated.

These anti-patterns share a common structure: they optimize for a dimension (abstraction purity, interface coverage, code size) that is not part of the temporal optimization objective. Each can be diagnosed by asking: "Does this boundary crossing save future changeset size proportional to its comprehension cost?" When the answer is no, the discontinuity is pure overhead.

*[Discussion — the anti-pattern diagnosis question is a direct application of #der-change-investment to discontinuity creation. But "proportional to its comprehension cost" is informal — formalizing it requires a way to estimate per-discontinuity comprehension cost, which connects to the open empirical question about the $k$ value per boundary type.]*

## Working Notes

- Reproducibility for the Discussion's measurement: `02-tst-core/empirical-discontinuity/elapsed_time.py`, with the `git log` command and each history's HEAD in its header, and the toolkit's `README.md` for the full tables. Every number in the Discussion is printed by the script; the capped and window-free treatments are its sections (1)–(5) and (6)–(7). Its docstring states the pairing rule (squash merges out) and the author-day bootstrap.
- Regression guard: a session cap is not a neutral filter for this test. It drops more gaps at high $d$, and a pure exponential passed through it comes out looking like a power law. A form test on capped gaps needs a null simulated through the same cap, or a treatment of long gaps that keeps them. To be released as a citable code/data supplement at publication.
- Regression guard: a time *estimated* from files and lines changed cannot test this hypothesis, because $d$ is built from the same files. Fitting such an estimate returns $\alpha \approx 0.12$ even when the estimate has no per-file term (`empirical-discontinuity/reproduce_estimate_fit.py`). Any future measurement needs a time that is not a function of the changeset's counts.
- The key open question is empirical: does the cost scale with discontinuity *count* (as stated) or with discontinuity *dependency structure* (as AAT's deliberation-cost framework suggests)? These make different predictions: the count model says 10 independent scattered changes are as hard as 10 interdependent ones; the structure model says the independent case is much easier. The count side is now measured, at heuristic tier, as showing no compounding (Discussion). The structure side needs a per-commit dependency measure among the changed locations, for example co-change coupling or static call/import edges between them, and a time measure closer to working time than inter-commit gaps, such as IDE or agent-session instrumentation.
- For AI agents, context-switch cost may have a different profile than for humans. LLMs can hold large contexts but may have difficulty with *deep* reasoning chains. This suggests the structure-dependent model (where chain depth matters more than context breadth) may be especially relevant for AI agents. A competing hypothesis from the original TST synthesis gives LLM agents a sublinear cost in discontinuities: logarithmic, or linear until an effective context width and then saturating. It proposes position-dependent retrieval loss in long contexts as the mechanism (Liu et al. 2024, "Lost in the middle: how language models use long contexts," *TACL* 12, 157–173). That mechanism concerns where information sits in a context, not how many crossings a task needs, so the link is the hypothesis's own proposal. Agent session traces, which record every file read, would test human-versus-agent cost profiles directly.
- If the exponential form holds, it has strong architectural implications: any design that reduces the number of boundary crossings for typical features is worth disproportionate investment. This amplifies #der-change-investment far beyond the linear model.
- TST's notation $k^{\text{discontinuities}}$ uses "discontinuities" loosely. A more precise formulation would count boundary crossings weighted by boundary type ( #def-discontinuity-distance), or better yet, measure the depth of the dependency chain among the scattered changes.
- A formal route from the count-vs-structure open question above to a structure-sensitive operator scaling is sketched in `spikes/spike-transient-dependency-amplification.md`: cost scales with the operator norm of a finite-horizon product $\lVert J_{F,d}\cdots J_{F,1}\rVert$ of feature-local Jacobians rather than with raw discontinuity count. The spike's affine sub-scope recovers $k^d$ as a uniform-per-block-gain special case (each discontinuity contributes the same $k$), which preserves this hypothesis as a scalar approximation while upgrading the underlying theory to dependency-structure-sensitive form. Promotion to a derived TST result is blocked on the spike's open obligations: formal $\widehat J_F$ construction from TST quantities, nonlinear-remainder bounds, cyclic-dependency treatment via SCC condensation, and empirical validation.
