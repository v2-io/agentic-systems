# `bin/lib/segment_renderer.rb` `strip_working_notes` truncates each segment at its last `## Working Notes` heading for the `--public` build, and in 22 segments the footnote definitions sit after that heading, at the end of the file. The public build therefore drops them, while the body references stay: `CURRENT-VOL1.md` carries `[^cat-2026-05-22]` (in the #der-directed-separation Related Work table) and `[^khalil2002]` with no definitions. The definitions lost include exactly the honesty markers on unverified citations (`[^cat-2026-05-22]` and `[^bg2-2026-05-21]`, 'verification-deferred'; `[^recall-2026-10-30]`, 'checked only bibliographically'), so a public reader meets those citations unmarked. Fix the tool: keep trailing footnote definitions when stripping Working Notes (or have the renderer collect `[^…]:` lines wherever they sit), then regenerate the CURRENT-VOL snapshots. Moving the definitions above `## Working Notes` in each segment would also work, but the convention is repo-wide and the tool is the one place to fix it. Until the tool keeps them, I.5's Working-Notes cleanup must not delete these definitions with the notes.
