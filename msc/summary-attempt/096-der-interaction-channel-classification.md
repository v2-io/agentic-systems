# Interaction-Channel Classification — Recipient-Side (derived — conditional)

The same signal from one agent lands on a recipient as one of *four qualitatively different things* — determined by three independent boundary conditions stated entirely in the recipient's existing AAT quantities. The emitter-side collapse of this variation into a scalar coupling-times-tempo loses information that is *load-bearing*: the recipient's repair path depends on which regime the event falls into, and "more tempo" versus "different model class" address structurally different failure modes.

Two event-level quantities are carefully distinguished and *must not be conflated*. The **magnitude** of the event in the recipient's observation space (how large a perturbation it produces in mismatch on arrival). The **information content** of the event conditional on the recipient's prior (the formal mutual-information quantity). A large-magnitude already-predicted event has large magnitude but small information content; a tiny-magnitude structurally novel event has small magnitude but large information content.

Three independent boundary conditions then produce four regimes. **Regime I — informative update**: event magnitude within the sector-condition region, information content representable within the model class, and above the observability floor. *This is the good case* — the event registers, gets processed, drives a useful update. **Regime II-a — magnitude shock**: event magnitude *exceeds* the sector region — too large to be absorbed by the correction mechanism. The repair is *more bandwidth or more tempo* — give the correction machinery more capacity. **Regime II-b — structural shock**: event magnitude is within the sector region but information content *exceeds the model class*. The class lacks the representational capacity to absorb what the event tells you. The repair is *structural adaptation* — a different kind of model. More tempo doesn't help here; the floor is class-level, not rate-level. **Regime III — ambient erosion**: event below the observability floor — individually small enough to be processed, but the cognitive overhead of processing accumulates. *Death by a thousand memos*. The repair is *infrastructure-level filtering* before signals reach the agent.

The framework's central methodological move: **the emitter sees a scalar; the recipient sees a regime**. Most multi-agent frameworks treat coupling as a single coefficient (the emitter-side view). The recipient-side classification names what that coefficient hides: events of identical scalar magnitude can sit in any of the four regimes, and *what to do about them is different in each case*. Conflating them — which the scalar emitter view does — confuses diagnosis.

A concrete operational consequence the framework draws out: **DDoS-of-low-priority-alerts is a real attack, not just inconvenience**. The regime III ambient-erosion case exists *not because the events are individually significant* but because *processing them consumes tempo that should be going to actual work*. A flood of low-content events drives the recipient into a state where it has no tempo budget left for the work the regime would normally allocate to. The repair is *not* faster processing of each event (that just consumes more tempo); the repair is *filtering at the infrastructure layer* before the events reach the agent's attention.

For LLM-agent infrastructure design this maps directly: **regime III filtering at the infrastructure layer is operationally critical**. An agent system that processes every event at the model level — every notification, every minor signal — will be overwhelmed by tempo cost even when no single event matters. The framework's prescription is to push regime-III filtering *below* the model level into the wrapper or system infrastructure.
