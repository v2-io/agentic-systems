# Observability Dominance (derived — robust-qualitative)

A direct consequence of the gain principle applied to strategy edges. **Unobservable strategy edges cannot be updated** — the gain principle drives their update rate to zero. The agent's effective strategy is therefore limited to *the parts it can observe*, regardless of the nominal confidence assigned to unobservable paths. Observability dominates nominal confidence in determining which strategies are epistemically alive.

The reasoning is concrete. The observability of a *path* through the strategy DAG is the minimum observability among its nodes — the weakest link determines it. When any node along a path has near-zero observability, the gain principle gives the edges touching that node a near-zero update gain: the edges are *frozen at their prior*, and the agent cannot update them regardless of what happens.

A striking structural prediction follows: **unobservable regions of strategy are absorbing**. Once significant strategy investment operates through unobservable nodes, the dynamics become self-locking — frozen beliefs mean no mismatch signal, no mismatch signal means no reason to revise, and the agent *cannot learn and cannot recognize that it cannot learn*. Escape requires external shock, proactive observability investment (instrumenting previously unmonitored nodes), or another agent whose observations cover the blind spot.

The framework draws operational consequences. An agent choosing between a strong-but-blind path (high confidence, low observability) and a weak-but-visible path (lower confidence, high observability) should prefer the *visible* one — after one attempt the visible path yields large update gain (the agent quickly learns whether it works and can redirect) while the blind path yields tiny gain (the agent is still guessing after many attempts). Observability *enables learning*; opacity *prevents* it.

In organizational settings the prediction is sobering: departments with poor measurement (R&D, strategy groups, some management functions) will develop persistent, untested beliefs about their own effectiveness — the theory predicts this is *structural* (frozen update gain), not motivational. In the software domain, code quality directly determines node observability: well-structured code with good tests makes strategy steps (features, refactors, deployments) observable; poor code quality reduces observability and freezes the developer's causal beliefs about what changes will accomplish. This makes code quality a *strategic concern*, not just an aesthetic one.

A subtler observation: an unobservable intermediate doesn't just freeze the touching edges — it makes *per-edge identification impossible*, forcing the agent into plan-level aggregation. The agent can still track plan success as a single quantity, but loses diagnostic resolution: it knows the plan is failing but cannot localize which step needs revision. The framework quantifies the *observability investment tradeoff* — making an intermediate observable yields a measurable improvement in the strategy-layer sector parameter (from the plan-level rate to the per-edge weakest-link rate), with the improvement positive whenever per-edge success rates are reasonable and experience is distributed across edges. The value of instrumenting an intermediate node is the *difference in sector parameters*, which translates directly to persistence margin.

A trade-off with chain depth is also surfaced. Finer decomposition (more intermediate nodes) provides earlier failure detection — detect a problem at step $k$ rather than discovering it at step $n$. But finer decomposition also increases the number of uncertain edges, compounding through chain confidence decay. The optimal decomposition depth balances *incremental confirmation against compound decay*: decompose as finely as observation channels allow, but no finer.
