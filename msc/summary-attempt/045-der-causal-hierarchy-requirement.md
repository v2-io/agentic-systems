# Causal Hierarchy Requirement (derived + scope — exact)

The direct application of Pearl's causal hierarchy to the value object: the action-value query in Part II uses Pearl's $do(\cdot)$ operator, so it is a *Level-2 (interventional)* query. By the strict-non-collapse theorem, Level-2 quantities cannot in general be computed from Level-1 data alone. Therefore an agent that must evaluate the action-value *from experience* needs access to **Level-2 knowledge** — knowledge about the effects of its own interventions, not merely correlational patterns.

The framework draws a sharp *scope narrowing* here: attention restricts to **learning purposeful agents** — agents that must *acquire or refine* Level-2 knowledge during operation. This is a named sub-scope of the agency scope, and it excludes agents with *pre-compiled* interventional structure: PID controllers (where the designer pre-computed the control law), LQR (where the separation principle gives the optimal policy from model parameters), hardcoded reactive policies. Pre-compiled agents are still within the agency scope (they have objectives and act on them) but outside the learning-agent scope — their causal structure was externally supplied by a designer who had Level-2 access. *All remaining Part II results operate within learning-agent scope unless explicitly noted otherwise.*

The derivation is exact: it is a direct application of the causal hierarchy theorem to the value-object definition. If one accepts that the action-value is an interventional query (which the do-notation makes explicit) and that the causal hierarchy is strict (an external theorem), the conclusion follows. The scope narrowing to learning agents is a definitional restriction, not a derived result — it sharpens the class of agents under study.

The distinction between intervention and conditioning is treated as the *core* of causal inference. It matters whenever the agent's action-selection policy correlates with unobserved confounders — which is generic for any agent that has internal state, plans, or memory. Three concrete examples are given. A developer needs to know "if I refactor this module, will tests still pass?" — not "modules that were refactored tend to have tests that fail" (the latter is biased by which modules the team chose to refactor). A commander needs "if I move forces north, will the enemy respond by retreating?" — not "when forces moved north, the enemy often retreated" (the latter conflates the commander's choice-causes with the enemy's response). A reinforcement-learning agent needs the interventional action-value, not the conditional expected reward given that the action was selected (the latter includes selection bias from the agent's own policy).

An empirical bridge to Hafez et al.'s framework is noted. Hafez's *Information Digital Twin* — a sidecar that monitors the agent-environment loop's information geometry — detects environmental perturbations at 89% accuracy versus 44% for reward-based monitoring. This is *consistent with* the present segment's claim: the feedback loop provides richer (Level-2) data than outcome monitoring alone. Hafez's framework measures the coupling; AAT explains *why* the coupling is information-theoretically superior — because the loop generates interventional data by construction, not merely associational data. Measurement and explanation are complementary.
