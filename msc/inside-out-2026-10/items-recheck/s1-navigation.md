## 3. For the vsect builder: what the tool and the import got wrong

**3.1 A closed recheck cannot be amended, and I needed to.** Several of my events contain misstatements (section 7); `vsect recheck` on a closed item answers "is not an open item", and `ask` and `note` do not attach to a closed judgment. A way to record a correction as a second event on the same item (`recheck --amend … --why`, with the earlier event kept and the correction shown beside it) would fit the "events are never edited" rule. Until then each correction lives in a document like this one, which I.8 will drain.

**3.2 The units hid real items in all five files.** `checkboxes` took `- [ ]` lines but not numbered `N. [ ]` lines or the nested sub-checkboxes: PRACTICA's cycle-priority list (lines 22-25), its findings pipeline (46-50), the process root (55), the README sub-bullets (74-76) and the four naming items (103-106) are all missing, and lines 103-106 are real work. TERMINOLOGY-TODO was imported as `bullets`, which skipped sections D (the thirteen deferred rows), E (the tetrad names, a paragraph) and F's five-step recommended reorganization. BIBLIOGRAPHY-TODO's "Status at a glance" and boundary table are not items but carry facts (the stale `ref/INDEX.md` statement was one). TODO.md's "Phase 2 semantic index" heading (line 322) is the same item as PRACTICA line 118 and was not imported on the TODO side. In each case a `sections` unit with a reading pass would have found them. The cost of the hole was that "every item from this file is judged" (the deletion condition) was true while real content was still only in the file; I carried each such piece by hand (section 5).

**3.3 The id suffix does not disambiguate.** Three of my BIBLIOGRAPHY items (`adding-entries`, `verifying`, `build-pipeline-emit`) share the suffix 975f, and several carry section chains taken from bash comments inside code fences, as the pilot reported. The suffix looks like a hash of the wrongly parsed section chain (I did not check the code), which would explain why the three differ only by slug.

**3.4 Smaller points.** The `holds` file keeps the verbatim title, so the restated frame sits only in the frontmatter `restated:` value, as the pilot suggested it should; a reader scanning `vsect open` sees the old title. `duplicate --of` accepts a target that another lane may later close as stale; a `vsect check` finding for "duplicate of a closed item" would catch that. `recheck --owner` checking against INTENT worked well. Commits scoped by path were easy because events live under `.vsect/events/item/<slug>/`.
