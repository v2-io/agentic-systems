# The system around ASF, an owner's read

Joseph's frame governs: this serves truth about agency, and the system around the theory earns its place only where it makes the theory say true things more clearly and reach a reader. "Thoughts about this as a system in and of itself — a system of agentic truthification about agentic theory — is wholly worthy." I take that as the brief and I take the system to mean: how a result gets found, checked, recorded, landed, and told.

## 0. The short version

1. **Finding and checking work.** When a result lands here it lands well. Today's F72 landing is the shape at its best: a verifier re-derived from the recurrence as written and caught that the May verification had checked the formula against itself; an integrator re-derived the replacement cap by a second route and ran an exact simulation; the notes say who checked which section and where the work order was wrong. The de-novo audit is the strongest instrument in the estate and it runs on bare hands. Whatever "smaller" means below, it does not touch the unprimed read, the bare brief, or verifier ≠ author.
2. **The system is built of checks and gates that nothing fires.** Four checks are commands, and they split cleanly: the two whose output asks nothing of anyone pass today (`check-links`, `refresh-all --check`); the two whose output demands action have failed for months (`lint-outline` has exited 1 with the same ten violations since May; 68 files fail the md-press gate the SOPs prescribe, eight of them SOPs). Everything that depends on a person remembering has stopped: no hook exists, and none has run since `core.hooksPath` was left pointing at a retired path; Gate 4 never fired; the gold gate convened once; the decision valve had no decisions; "released to the standing cycle" names a cycle with no clock. Sessions per month from June to October ran one to nine. The system assumed a cadence it never had, and the people-gated steps are where it failed. (§2)
3. **Its memory is keyed by where things came from, not by what they say.** Thirteen tracker files, every section headed by a date or an audit id; `status:` a hand-set projection that two readers set in opposite directions over the same text; Working Notes an unresolved-state database by accident, 17% of segment text, with no item status and no owner. So "what is open about $X$, and how sure are we" costs reading everything, and Joseph's lost clarity is the same fact seen from the reader's chair. (§3)
4. **Hand-set surfaces drift; generated ones hold.** README, FINDINGS and the readme partials are generated with a `--check` and are current today. The front door, the outline captions, `status:`, the spike INDEX and every tracker are hand-asserted and are the places every reader in this effort found stale. The project already knows the fix and uses it on the six surfaces that matter least to truth. (§3, §4)
5. **It reviews itself into more record.** This is at least the seventh review of the system since March; `measurements.md` lists them. Each was right, each added a layer, and the July review warned that any map of the processes "must define its own drain or it becomes the next un-lifted pool." It became one. This document names its own exit. (§5)
6. **Smaller.** The lead's suspicion holds, with evidence: the system needs five surfaces where it has about thirty, and a trigger that is a tool event rather than a person. The retire list, each with its reason, is §6.
7. **Objective I's key results**, ranked, each with what "done" looks like and what would refute it, are §7. The test each must pass is the lead's own: can a newcomer tell from the files which claims are established, by what, and which are not, without trusting whoever wrote them? Today they cannot.

## 1. What works, and must not be pruned

The generation and verification half of the system is healthy, and the record shows it rather than asserting it.

- **Role separation with re-derivation.** Spiker, verifier and integrator as different agents; the verifier re-deriving "from what is written, not from what seems meant"; the integrator taking a second route. The 2026-08-22 impl pass (inventory agent, writer, different-substrate verifier, each catching a hole the others missed), the Aug-24 decomposition cluster (refuted by audit 592047, repaired the same day), and F72 today all have this shape. The owner review tested the hypothesis that landings waited on Joseph and refuted it: derived results landed the same day they were spiked.
- **The de-novo audit.** The one instrument whose output outside readers (the Fable 731548 audit, Codex 526815) consistently proved right against the project's own verifications. It needs an unprimed reader, a two-line brief and nothing else; the July review called it the crown jewel and noted it has no scaffolder, no state and no trigger. Protect the method; the rest of this document is about giving it a clock.
- **Generation with a diff check.** `bin/refresh-all --check` regenerates six surfaces in a temp copy and diffs; it is clean today. This is the proven mechanism for keeping a derived surface true, and it exists in this repo.
- **Three append-only records already exist.** `bin/term decide` writes a decision event per term, never edited; `empirica/`'s RUNS contract binds an empirical claim to a dated run with its seed; relata records verification acts per citation. Each is the shape the census says claims lack: an act, by someone, on a dated version, that a later reader can trust without trusting the author. The claim-level record proposed in §7 is these three, applied to derivations.
- **Honest self-marking.** Trackers that say they are stale, a SOP that says it is "unscarred", an INDEX that calls its labels "a convenience record, not ground truth." This honesty is real and it is also the symptom: a surface that must warn you not to trust it has stopped being a surface.

## 2. The fault: checks that nothing fires

The three readings converged on a stalled integration stage and an arc with no owner. I checked them where I could and they hold (§9). But I think they name a symptom twice. The cause is one level down and it is mechanical.

| `bin/lint-outline` | at cycle close | an agent remembering | exit 1 since May; the ten violations are the ten the July valve listed; 5 missing deps; 3 rows marked `missing` whose files exist |

Read the right column against the sessions column in `measurements.md`: one session in June, nine in July, four in August, two in September, six in October. Every mechanism that needed a person to remember it, or Joseph to attend to it, decayed at exactly that cadence. Every mechanism that was a command held whenever someone ran the command. The July review said "un-clocked queues driven by a single human clock"; today's standing lifts the human gates. That removes the clock. It does not install one.

So the test for every mechanism under objective I is a single question: **does it fire without a person remembering?** If it does, keep it. If it does not, it is a wish, and the record shows what wishes do here: they become a tracker row, the row becomes a hand-off, the hand-off becomes a phrase in an SOP, and three months later a reviewer finds the phrase. The owner review's "the arc has no owner" is true, and an owner who is a role in a document is the same wish one more time. The owner has to be an event: a commit touching `src/` that regenerates or fails a diff.

Read in the theory's own terms, the system fails the persistence shape it proves: the checks are its correction, the record drifts every time a result lands, and a correction that no event fires has rate zero against a drift that never stops; by Part I's own inequality the mismatch leaves every bounded region. That is not an analogy I am reaching for; it is the mechanism the right column of the table records.

A corollary about the standings set today. "Gates on Joseph are lifted" and "resolve uncertainty rather than route it" are right, and they are also the fourth time the project has told agents to stop waiting (2026-05-18 §0c; 2026-07-14 on stage; 2026-07-15 the valve's lead-recs; today). Instructions to agents have not changed this behaviour in five months because the behaviour is downstream of the record: an agent that cannot see whether something was decided files it as undecided. The repair is the record, not the instruction.

Third, honest uncertainty. Joseph's own position, recorded in routing.sop §9 and AGENTIC-DELEGATION, is that the lived texture and the scars are what make an orientation work, and that a flatter checklist would be "a less true document." I do not have evidence against that and some for it: the F72 verifier's posture ("re-derived from what is written, not from what seems meant") is the routing SOP's §0 internalized. So the proposal in I.6 is not to flatten the disposition; it is to move every rule a tool can check out of prose and into the tool, delete the rule's prose, and measure whether the named failures recur rather than argue about it. The project has a comprehension instrument for the theory (`msc/quiz-responses/`); it has none for the process, and a cheap one exists: launch two cold agents on the same task with the long and the short orientation and count the named failures.

On what replaces the gate words now that gates are lifted: 26 live files still say "Joseph-reserved", "awaiting go-ahead", "external-eye gate" or "Joseph batch." Ranked by how much each changes what a newcomer can tell from the files alone. Each is one line, a done-criterion, and what would refute it. D owns the arc's content and the definition of its trigger; I owns that the trigger is a tool event and that the record exists for D to run on.

- **I.2 — The checks fire without a person.** A tracked hooks directory (`.githooks/`, `core.hooksPath` set in the setup step every agent runs) runs `md-press --check`, `bin/lint-outline`, `bin/check-links` and `bin/refresh-all --check` on the files a commit touches, and a commit that fails them is refused; the pre-existing debt is cleared first (68 files, 10 violations, 5 missing deps, 3 stale `missing` rows) so the gate starts green. *Done:* the hook exists in git; a deliberately broken commit is refused; `lint-outline` exits 0. *Refuted if* the hook is routinely bypassed with `--no-verify`, which would mean the checks are wrong, not the hook.

  Design notes for the implementer, each measured on 2026-10-30:
  - *Cost is not an objection.* `bin/lint-outline` 0.04 s, `bin/check-links` 0.6 s, `bin/refresh-all --check` 0.9 s, `md-press -q` on one segment 0.01 s (cached). The whole set runs whole-repo on every commit; no "only when `src/` changed" carve-out and no pre-push tier is needed, which removes the usual reason hooks get bypassed.
  - *`core.hooksPath` is local config, not tracked,* so a tracked `.githooks/` still needs each clone to set it once, and until it does I.2 is a person remembering. The self-installing form: whatever every session already runs first (`bin/refresh-all`, or the session-start step the orientation names) sets `core.hooksPath .githooks` when it is unset. The retired path it pointed at until today (`8e7ba56d`) is worth one look in case a program-level hooks directory under `~/src/arch/` was once intended; none exists there now.
  - *md-press's unsure decisions.* `md-press -q` exits 1 on unsure decisions as well as confident ones, so a hook that blocks on it is bypassed the first time an agent hits an honest "unsure." The debt-clearing pass handles this if it is done per file with `--fix` and `--toggle` rather than by hand: a flipped join is marked in the file and never re-asked, so after clearing the gate is stable and a new exit 1 means a real change. Clear the eight failing SOPs this way first, as the dry run.
  - *`lint-outline`'s debt is mostly not debt.* Nine of its ten ordering violations are 03/04 `scope-*` rows placed before their dependencies, which reads as deliberate scope-first pedagogy with no record; they clear through `OUTLINE-accepted.md` files for 03 and 04 (the mechanism proven in 01), each row citing the reason. The one 01 row (`impl-persistence-and-limits` before `result-per-dimension-persistence`) is a theory call decidable on the merits; the segment's own note says the result belongs in Part I. The three stale `missing` markers and the five 03 missing dependencies are honest marks: the hook accepts a `missing` row and fails only on a dependency that names no file and no `missing` row.
  - *The hook names the file and the check.* Under the parent-commits standing, a failure lands on the parent's commit for an agent's edits, which is the right place for review; so the output must say which file failed which check, not only exit non-zero.
- **I.3 — One open ledger, keyed by claim.** A single file (or one per volume) of open items, each with a slug, a kind, a resolver and a date, where every slug and path resolves; the thirteen trackers, the two index files, the proposal files, ROUTING and the decision briefs are folded into it or deleted; an item closes in the commit that closes it, and the history goes to CHANGELOG.
