# Second-mind confirmations of the 36 lapsed (record, version) pairs

KR **I.4** ("Standing is read from recorded checks, not typed"), under the top intent: *"Complete "in-place" refactor of ASF-- meta, all artifacts, and theory itself."*

Recorded as `--by second-mind-confirmer --role second-mind`. Of the 36 pairs, 33 were judged `for-checks` and 1 `not-equivalent`. Each of the remaining 2 pairs bears on one of its checks and not on the others, so it was judged per check with `--checks` (arch 90e46e9): `not-equivalent` for the one check it bears on, `for-checks` for the rest. Each event's `criterion` field says what was compared. Afterwards, `vsect confirm` reports nothing awaiting a second mind. The dashboard shows 3 checks ended by a not-equivalent judgment, which need redoing, and 14 of the 29 checked records holding (2 before).

## How each pair was compared

I compared full texts, not `vsect confirm`'s diff, which cannot be judged from (see *Tool findings*). For each pair I read both versions with `vsect read <id> --at <full hash> --bare`, the old from the hash in the check events' bases and the new from the current file, whose version I verified equals the pair's target. I diffed them word by word. I removed any `## Claim Record` section from both sides and diffed again, which separates pure record insertions from body changes. Then I read each re-bound check's full criterion in `reviews/*.md` and asked whether any changed sentence is something that check reads. `for-checks` was recorded only where the answer was no for every listed check. `equivalent` was not used: no pair was a pure no-op, and most add or correct claims.

## What this says about the lapse rule (design input for vsect)

The strict transitive-`depends:` basis is costing more confirmation work than it buys truth. There were 36 pairs carrying about 120 (pair, check) bindings. Exactly three of those bindings were touched by their change. Every other judgment was "this check reads nothing of that upstream text". That is a real comparison, but a repetitive one, and doing it 117 times trains a confirmer to stop comparing. The worst case is `#scope-adaptive-system`. A redefinition of its $\pi_0$ rule lapses Kalman–Bucy closed forms, RDF limits, B.1 record checks and F72 algebra, because all of them sit downstream of it. Before these judgments, the two pairs on that one record held 25 checks lapsed, and only 2 of the 29 checked records held. One candidate: let a check declare, when it is taken, which records it actually read (a narrower *read set* inside the basis). Changes to those records lapse it strictly. Changes elsewhere in the basis would mark it "upstream changed, not read" and ask for a lighter confirmation, or none. The strict rule would stay the default when no read set is given. A second cost is that a pure `## Claim Record` insertion lapses every downstream check (13 of 36 pairs here). That is the record-grain question (`open.md` Q10). Carving records into statements would remove it.

## Tool findings, met while doing this

- **`confirm`'s diff cannot be judged from.** The normalized text is one line per paragraph, and the diff truncates each line at about 160 characters. A change after a paragraph's first 160 characters shows as a `-` line and a `+` line that look identical. This happened for `def-agent-environment` and `def-proprium-mapping`, among others. A confirmer who relied on that output would be judging blind. A word-level diff with context around each change would fix it.
- **The pair could only be judged as a whole.** `for-checks` scoped to every check on the pair, and `not-equivalent` was unconditional. This was fixed during this work by `--checks` (arch 90e46e9), and the two mixed pairs were recorded with it.
- **`read --at` with a short version fails** with "not in .vsect/objects/ and not reproducible from git". The `confirm` listing prints only short versions, but the version can be reproduced from git: the full hash works. Either a prefix match or a different error message would avoid sending the next reader down a wrong path.
- **A `not-equivalent` pair used to stay on the `vsect confirm` list.** This was fixed in the same commit (arch 90e46e9). It now shows as "checks ended by a not-equivalent judgment (redo them)".
- **Re-padding a markdown table changes the version** (`def-eli-cohort`). The normalizer reflows paragraphs, but not table cell padding.
