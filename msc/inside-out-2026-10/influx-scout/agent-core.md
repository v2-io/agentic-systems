### 2.A `plugins/sidecar/notes/strategy-dag-engineering.md` — the strategy DAG, read as a specification

*Written 2026-10-07 by an Opus 5.5 instance at Joseph's ask ("I need to get an engineering perspective on the strategy-dag -- everything we know about it or can prove about it or its constructive needs and relationship to the information cascade…"). 386 lines; [read whole].*

What it is: the most careful reading of Part II's strategy chapters I found. Each claim is tagged by its canon tier and translated into what it obliges a builder to do. Its glossary (plain meaning first, then the slug) is itself a teaching asset; the asf-transcribe builder called it "the model for other notes".

Material for the integrator, by kind:

- **A "what canon establishes" table (§2)** with fourteen claims, each with its tier and builder meaning. This is the closest thing on the drive to a statement of *what the strategy-DAG theory claims*. Useful framings: acyclicity is exact *for time-indexed event tokens*; AND/OR with single-parameter edges is a *chosen* representation (three attempts converged; noisy-OR rejected for a demonstrated reason); status propagation is exact computation; per-step attribution is #P-hard in general and trivial when intermediates are observed; plan-level persistence (Prop B.5) needs no credit assignment. Its one-line synthesis: *"The theory's guarantees all point at one engineering lever: make intermediate nodes observable."* It cites `#disc-credit-assignment-boundary` saying the same: credit assignment is "primarily an observability design problem, not an algorithm design problem".
- **A gap in canon, new: types vs tokens (§4.1).** Acyclicity is derived for one-shot event tokens, but every credence result (Props B.1–B.7, `#example-strategy`) learns across *repeated trials of the same edge*. In a real plan most edges are traversed once. The two results presuppose different objects, and canon never states the bridge (template/instance, plate notation, parameter tying). The author grepped 01–03 and found nothing. It proposes a short segment: the edge-*type* library carries $(\alpha, \beta, \lambda)$, tokens read priors from and write outcomes to it, and the binding granularity is a modeling trade-off (too coarse pools heterogeneous $\theta$, a type-level correlation-hierarchy problem; too fine starves evidence). It also reconciles two earlier opposite splits (Track-A "structure persists, weights re-estimated" vs operata's HTN methods) as halves of one object: *an HTN method is a type*. Canon check: segments mention neither template nor plate [grep]. The "type/token" grep hit 68 files on unrelated "token" uses.
- **Builder gaps canon itself names as open (§4.2–4.5):** topology acquisition (grafting has no operator); the AND/OR test misclassifies $k$-of-$n$ (an auditor off-ramp on `#scope-and-or`, which the author re-checked); the per-node properties dropped from the origin document (`props_t`: agency, observability $\sigma$, value, horizon; canon still uses $\sigma_v$ and $\iota_{ij}$ without defining a node-property field); computable proxies for $A_O$, $\Phi$ and $\rho_\Sigma$.
- **The alignment reading (§5).** An LLM is Class 3, so it can't maintain its own DAG goal-blindly. The note reads `#hyp-truth-serving-loophole`'s *goal-declared* discipline (Joseph's own hypothesis, `sketch`) as the constructive answer: a DAG held out of band, written only through a tool. The design rule it holds hardest: *a node is satisfied when a goal-blind check says so, never when the planner says so*. It then uses canon's composition result (`#def-strategy-dag`, "Composing heterogeneous strategy DAGs": no exact joint DAG exists when shared sub-orders conflict; irreducible defect $\varepsilon_\Sigma^{\ast 2} = \sum_C \mathrm{TC}(\{s_v\}_{v\in C}) \le \lvert S\rvert \log 2$) as a computable measure of *disunity of intent* between two declared plans. The formula is canon; the use is new. §5.5 maps ai-risk-model's "Aligned to whom?" diagram onto ASF objects. That bears on region 7.
- **Implicit strategy (§5.6).** Canon allows a strategy nobody stores: `#def-strategy-dimension` ranks representations from none to an explicit DAG, and `#result-coupled-diagnostic-framework` calls the $M$/$G$ split "analytical, not architectural" for a coupled agent [verified, line 36]. So the DAG is a *model an observer can ascribe* to any agent that decomposes and tracks progress, and a *stored structure* only for agents built that way. Canon says this only in a Working Note (`#def-strategy-dimension` line 86, "$O_t$ / $\Sigma_t$ as *ascribed* decomposition vs *literal inspectable* internal pair") [verified]. §5.6 also states, as a design truth, that **an ascribed DAG has structure, not numbers**: none of the quantitative machinery applies to a DAG read off a transcript without invented credences, except via type frequencies across many sessions. (The arch 10-19 critique calls this the "No Numbers Fallacy". The two disagree; see §8.)

It reconciles that with Joseph's 2025-12 support for an execution-order layer through `spikes/.integrated/spike-fsa-dag-relationship.md` ("Lossy — discards credences, AND/OR structure, causal semantics"): an ordered list is legitimate as a *derived view* and harmful as a *stored substitute*.

### 2.D `spikes/middle-fold/` — in-place context folding, and an audit of how canon was used

*2026-10-21; Opus 5.5 then Fable 5.1. [read whole]: README, `debrief.md`, `proposed-integration-plan.md`, `notes/asf-citation-audit.md`; not read: `notes/design-space.md`, `de-novo-feedback-1.md`, code.*

- **`notes/asf-citation-audit.md`** is the most reusable document in the spike. It audits the 2026-10-19 arch note (`~/src/arch/msc/context-saliency/notes/aat-strategy-epistemics-and-middle-folding-2026-10-19.md`, region 3) against canon at `4ee2b895`:
  - **The central finding is a type error that clarifies what canon *is*:** $\Sigma_t$ ranges over *future* event tokens (`#deriv-graph-structure-uniqueness` "$\tau_i \gt t$"), while a finished subgoal's interior is *past* history in the append-only chronica. For an LLM that history is carried in context, which canon treats as $M_t$ (`#obs-context-turnover`). So **a context fold is a compression of $M_t$ relative to $\mathcal C_t$, judged by model sufficiency $S(M_t)$**, and CMC says nothing about it. Its §7: *"which canon object is a context fold an operation on?"* The same question, asked of any proposed application, would catch a whole class of misapplications.
